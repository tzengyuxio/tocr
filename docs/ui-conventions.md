# 介面慣例

程式無法強制這些規則，但畫面的一致性靠它們維持。建檔準則見 [data-conventions.md](data-conventions.md)。

## 畫面上叫「雜誌」

`Magazine` 這個模型在**畫面上一律寫「雜誌」**——導覽列、麵包屑、後台的「雜誌管理」「新增雜誌」、表單的欄位名與驗證訊息、匯入匯出的說明文字都是（2026-08-22 起，原本寫「期刊」）。

理由是讀者的話：這個站收的是《軟體世界》《電玩通》這類消費性刊物，一般人講的就是「雜誌」；「期刊」在中文裡更常指學術期刊，讀起來像另一種東西。

**程式與文件內部仍用 `Magazine` 與「期刊」**：模型名、路由 `/magazines`、`magazine_name` 這類 CSV 欄名都不動——那些是識別碼，改動的成本落在資料與網址上，而換掉的理由只在措辭。唯一的例外是 `issn` 的說明「國際標準期刊號」，那是 ISSN 的正式中文譯名，不能改。

## Chip

掛在文章上的三種標記——**分類、遊戲、標籤**——在前台與後台共十幾個頁面出現。它們一律使用 [`src/components/chips.tsx`](../src/components/chips.tsx)：

```tsx
<CategoryChip category={article.category} />
<GameChip name={game.name} />
<TagChip tag={tag} />
<TagTypeChip type="COMPANY" />   {/* 標籤「類型」本身，不是某個標籤 */}
```

`TagTypeChip` 是獨立的元件而非 `<TagChip tag={{ name: "公司", type: "COMPANY" }} />`。曾經有五處這樣假造，看起來對只是因為 `TagChip` 原樣渲染 `name`；等 `TagChip` 加上 tooltip，那些地方就會顯示「公司標籤：公司」。

**不要自己刻 `<Badge>`。** 這條規則是從教訓來的：同一個分類曾經在文章管理頁是無色外框、在 OCR 複查頁是琥珀底加資料夾圖示、在單期頁又是另一個顏色配另一個圖示，而標籤則是全站都有顏色、全站都沒有圖示。

### 配色與圖示

| 家族 | 顏色 | 圖示 | 意義 |
| --- | --- | --- | --- |
| **遊戲** | **`violet-600` 深底白字** | `Gamepad2` | 文章提到的遊戲 |
| 分類 | `amber` | `FolderOpen` | 文章的欄目類型（特輯、攻略、評測…） |
| 標籤·一般 | `gray` | `Tag` | 未分類的標籤 |
| 標籤·人物 | `blue` | `User` | 製作人、繪師、藝人 |
| 標籤·活動 | `purple` | `Calendar` | E3、電腦展 |
| 標籤·系列 | `green` | `Layers` | 太空戰士系列、大富翁系列 |
| 標籤·公司 | `orange` | `Building2` | 智冠、SEGA |
| 標籤·平台 | `cyan` | `Monitor` | PS、SFC、PC |

分類與遊戲的色相由 OCR 複查頁選定，標籤的六色更早就在用。

### 遊戲比其他 chip 重一階

**遊戲是唯一不在 `-100` 色階的 chip**，它用 `bg-violet-600 text-white`。

這是刻意的層級差異，不是漏改。一篇雜誌文章講的是什麼，多半就是「講哪一款遊戲」——讀者在目錄裡掃的是遊戲名，而每一列同時還掛著分類與一兩個標籤。全部同一個色階時，最重要的那個會被淹掉。

曾經把它一起降到 `-100` 求整齊，被指出「遊戲對一篇文章而言最重要，不該是最不顯眼的那個」，改了回來。**視覺權重要反映重要性**，一致不等於一律相同。

### 圖示帶意義，顏色輔助

八個家族擠在同一個色階裡，色相並不可靠地分得開——`amber` 對 `orange`、`violet` 對 `purple` 都很接近。**辨識靠圖示**，顏色的工作是讓一整排 chip 好掃視，以及在同一列裡把不同家族拉開距離。

因此新增家族時，**先確定圖示分得出來**，再挑一個還沒被用掉的色相；反過來做會得到兩個只有色差、實際上認不出來的 chip。

### 色階

除了遊戲之外一律 `bg-{色}-100 text-{色}-800`。

選淡色階而非飽和色，是因為 chip 在目錄列表裡每列都出現——電腦玩家 96 期一頁就有 54 列。若每個 chip 都是飽和色，整頁會蓋過它們要標註的標題。留一個飽和色給遊戲，正是因為只有一個，它才跳得出來。

> 已知落差：這組顏色**沒有 dark mode 變體**，深色主題下仍是淺底深字。標籤的六色從一開始就是這樣，統一時沒有一併處理——那會擴到所有用到標籤的頁面。

### 不屬於這套語言的

- **篩選條件 pill**（搜尋頁的「分類：特輯 ×」）：那是目前的查詢狀態，不是資料本身，維持 `variant="secondary"`
- **標籤索引頁的標籤連結**：那是導覽用的按鈕（帶文章計數），類型已由分組標頭表達
- **信心度數值**（OCR 複查頁）：刻意不做顏色編碼，理由見 [features.md](features.md#複查編輯器)

### Tooltip

三種 chip 都帶 `title`（「分類：攻略」「遊戲：太空戰士8」「公司標籤：SEGA」）。這不是可有可無的——類型只由一個 12px 圖示和一層淡色承載，而上面才說過那個色階分不太開，tooltip 是讀者唯一的退路。

### 附加內容

編輯介面需要在 chip 上掛移除按鈕，用 `children` 加 `REMOVABLE_CHIP`（badge 預設會裁掉溢出的子元素，角落上的按鈕會被切掉）：

```tsx
<TagChip tag={tag} className={REMOVABLE_CHIP}>
  <ChipRemoveButton label={`標籤：${tag.name}`} onRemove={() => remove(tag)} />
</TagChip>
```

**不要為了掛按鈕就自己刻一個 chip。** OCR 複查頁原本有個 `ChipWithRemove` 自己組裝，結果變成顏色跟共用的走、圖示自己再挑一次——`chips.tsx` 換圖示時它會靜靜地留在舊的。

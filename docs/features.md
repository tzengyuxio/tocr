# 功能

## 期刊與單期

- 期刊 CRUD：名稱、原文名、別名、出版社、ISSN、創刊／停刊日期、刊頭圖
- 單期 CRUD：期號、其他編號、刊種、卷號、特輯標題、出版日期、頁數、定價、封面與封面資訊（遊戲／人物／繪師）、目錄頁掃描圖（可多張）
- 單期拖曳排序（@dnd-kit），批次儲存
- 文章列表拖曳排序，或一鍵依頁碼重排；列表上直接刪除單篇，不必先展開快速編輯
- 快速新增單期：Dialog 模式，不離開期刊詳情頁
- CSV 批次匯入：一次匯入多本期刊與其單期

ISSN 刻意不設唯一性、日期採 EDTF 等建檔準則見 [data-conventions.md](data-conventions.md)。

## AI 目錄辨識

上傳目錄頁掃描圖，由視覺模型擷取成結構化的文章清單。

- **三種 Provider**：Claude（Anthropic）、OpenAI 相容、Gemini（Google AI）。依環境變數自動偵測哪些可用
- OpenAI 那條走的是 OpenAI 相容協定，設定 `OPENAI_BASE_URL` 就能指向自架的模型服務
- 支援多圖：一期可以有多張目錄頁，單次請求上限 10 張
- 自動帶入該期已上傳的目錄頁圖片，不必重新上傳
- 辨識結果存進 `ocr_records`（辨識歷史），文章則直接寫進該期的文章列表

**辨識完直接落地**：`/admin/ocr` 只負責上傳與辨識，跑完就把結果寫成文章並跳到單期編輯頁，複查在那裡進行。這期已經有文章時會先問過，繼續就是**取代**整期——既有文章連同標籤與遊戲關聯一併刪除（`POST /api/articles/batch` 的 `replaceExisting`）。不提供「附加」，那正是重複文章的來源。

不帶 `replaceExisting` 時仍是單純附加，匯入腳本（API token）靠的是這個行為。

### 複查編輯器

複查就是編輯該期的文章，沒有另一套介面：單期編輯頁的文章列表左側是目錄圖預覽（可切換、放大），右側逐篇 inline 編輯，改的是真正的 `articles`。

- 行內可改標題、副標、頁碼、分類、作者、摘要，以及**相關遊戲與標籤**——後兩者以名稱輸入（逗號分隔），資料庫沒有的會建起來
- 可在任一列的上方或下方插入文章，補漏不必加到最後再拖
- 拖曳排序寫入 `sortOrder`

`tocReviewedAt` 由人在看完後按「標記為已複查」寫入，不再是儲存的副作用——辨識結果落地時還沒有人看過，那時標記等於謊報。**透過 API token 的寫入不標記**，無人值守的流程不能宣稱有人檢查過。

複查之上還有一層 **`completeAt`「完備」**：這一期的資料該有的都有了，不必再回頭看。**只有 ADMIN 設得了**，勾選在單期編輯表單、三態標記顯示在後台的兩張單期列表。標記之後只要這一期或它底下任何一篇文章被動過，就轉為「完備・已變更」等著重新確認；沒標示過的什麼都不顯示。三態怎麼存、什麼算「被動過」見 [data-conventions.md 的「完備」](data-conventions.md#完備)。

**公開頁標的是同一件事的另一半**（2026-08-31）：核對過而且沒被動過的期數，在刊系頁的單期卡片與單期頁標題旁掛一個淡的「已校訂」小框，其餘一律不標。換詞是因為「完備」是編輯的話、「完整」會被讀成整本都掃了；三態收成兩態是因為「完備・已變更」是內部待辦。公開 API 只回衍生布林 `isVerified`，兩個時間戳仍然只有 ADMIN 拿得到。

模型自評的信心度仍在辨識回應與 `ocr_records` 裡，但**畫面上不再顯示**：它隨辨識結果一起消失在落地那一步，而 `articles` 沒有這個欄位。原本也只顯示數值、不做顏色編碼——目前收集到的樣本全是滿分，顏色只會永遠是綠的，讀起來像「已檢查」而其實沒有。要不要換成比較實在的訊號（頁碼不連續、標題過短、缺頁碼）見 BACKLOG。

## 文章索引

- 標題、副標題、作者（可多位）、頁碼起訖、摘要、分類
- 分類是 Prisma enum，中文標籤存在 `src/lib/article-categories.ts`，改字不需要資料 migration
- 個別編輯與批次建立
- 關聯標籤與遊戲（多對多）

掛在文章上的三種 chip（分類、遊戲、標籤）全站共用 [`src/components/chips.tsx`](../src/components/chips.tsx)，配色、圖示與使用規則見 [ui-conventions.md](ui-conventions.md#chip)。

## 標籤

六種類型：一般、人物、活動、系列、公司、平台。標籤詳情頁依期刊、單期分組顯示相關文章，可展開收合。

## 遊戲

遊戲是獨立實體（平台、開發商、發行商、類型、封面），與文章多對多，可標記「主要遊戲」。詳情頁同樣依期刊、單期分組。

封面走與單期封面、期刊刊頭同一個 `ImageUpload`：拖曳上傳、貼網址、以及**清掉這張圖**（圖片右上角的 ✕）三件事都在。遊戲表單原本是一個裸的網址欄位加預覽圖，少了後兩者——RAWG 抓錯時唯一的退路是整個取消編輯。

另可透過 RAWG API 搜尋帶入（需設定 `RAWG_API_KEY`）。**回傳的是候選清單，不是一張圖**——RAWG 的搜尋是模糊比對而且幾乎不會回空結果，所以「找不到」很少發生，「找到錯的」才是常態：2026-08-22 拿 14 個真實中文遊戲名去問，14 個都回傳了帶封面的結果，但多半是別款遊戲（《A-6入侵者》問到 *Avernum 6*，《A-10坦克殺手》問到一款中國手遊）。程式分不出對錯，編輯看得出來，所以列五筆縮圖與年份讓人挑。

名稱與該遊戲任一名稱同鍵時標「名稱吻合」（用 `nameKey()`，與辨識、搜尋同一把尺），但那是**提示不是決定**——這批老遊戲同名不同作的情況多。

查詢依英文名 → 原文名 → 中文名的順序試，命中就停。RAWG 是英文資料庫，而站上的 `name` 是中文譯名，只送它幾乎必定問錯。中文名留在最後而不是拿掉，因為華文圈自製的遊戲反而可能只有中文名找得到。**注意 `Game.nameEn` 目前全站是空的**（975 款裡 0 筆），所以這條鏈在資料補上之前幾乎不會被觸發。

## 前台瀏覽

- 首頁以搜尋為主：搜尋框、統計數字、最新單期 16 期（寬螢幕 8 欄兩排）。有文章的排前面，不足才用有封面但還沒有目錄的補滿，避免空殼
- 封面一律完整顯示不裁切：雜誌封面滿是刊名與標題文字，填滿式縮放會把字切掉
- 期刊／單期／文章瀏覽
- 單期頁是雙欄：左側是封面與目錄頁掃描圖（sticky，任一張都可點開 lightbox 放大並左右翻），右側是目錄本身。掃描圖與索引同屏，讀者可以直接對照
- 目錄是一份響應式清單而非表格。頁碼與標題一行，遊戲與標籤的 chips 只在有值時才佔第二行——多數期的作者、分類、遊戲都是稀疏的，固定欄位等於用空格把列表拉長
- 期刊列表標出收錄的本數，可依分類（PC Game／TV Game／Online Game）篩選、依名稱或創刊日排序，並可在卡片與列表兩種檢視間切換，狀態走網址（`?filter=&sort=&dir=&view=`）；表在 `src/lib/magazine-browse.ts`，後台的期刊管理共用同一份表與同一條網址參數，只是不掛分類篩選（管理清單要看得到全部），並多一種「建立日期」排序——那是編輯才有的問題（剛才建的那本在哪），讀者不關心一筆資料何時被輸入，所以前台那組沒有它。**創刊日排的是衍生欄位 `foundedSort` 不是 `foundedDate`**——後者是 EDTF 字串，`1999-05` 與 `1994` 直接比字串會把年份小的排在後面；沒有創刊日的排在最後。**沒有任何刊物的分類不顯示 chip**——Online Game 目前一本都沒有，擺一個永遠是 0 的按鈕等於給讀者一個按了不會有事的控制項，等資料進來它自己會出現
- **期數講的是本刊**：期刊列表與刊系頁的「收錄 N 期」數的是 `kind` 為 `REGULAR` 的期，試刊與特刊分開講（刊系頁寫成「收錄 216 期，另有特刊 1」，列表的徽章塞不下就放 tooltip）。判準是這一冊有沒有拿到正刊的編號，見 [data-conventions.md 的「刊種」](data-conventions.md#刊種)。**已知總期數則是抄來的數字**，站上不替它分類；本刊數超過它時代表那個來源已被超越，做法是把它清掉，公開頁那句提醒是給編輯看的
- 遊戲與標籤索引。遊戲索引每頁 40 款、寬螢幕四欄，搜尋／篩選／排序全部走網址（`?q=&filter=&sort=&dir=&page=`），與期刊頁同一套；表在 `src/lib/game-browse.ts`
- **遊戲索引只有「名稱」與「相關文章數」兩個維度**，因為其餘欄位還沒有資料：624 款裡有封面的 1 款、有發行商的 1 款、有平台與發行日期的 0 款。平台與類別是 `String[]` 自由文字（沒有 Platform／Genre model），資料補進來再加 chip 即可
- 篩選的「多篇報導」＝相關文章 ≥ 2 篇（481/624 只被提過一次）。**Prisma 不支援對關聯筆數下 `where`**，所以先用 `groupBy` + `having` 取 id 再以 `id: { in: ... }` 回填；依文章數排序時必須補 `name` 當第二鍵，否則長尾的平手順序不定，同一款遊戲會在兩頁出現或一頁都不出現。**預設排序是「相關文章數」由多到少**（481/624 只有一篇，A-to-Z 的第一頁等於一頁沒人寫過的遊戲）
- **列表檢視**（`?view=list`）是卡片牆之外的另一種讀法：出版社、發行期間、分類、期數排成欄，一眼掃得完全部刊物。欄位是讀者要的那組，不是照抄後台那份（後台有編輯、快速新增單期、建立日期），所以兩邊各有元件而不共用。沒有用 `<Table>`——那是 `"use client"`，而這頁整條是伺服器算好的；窄螢幕表格也擠不下五欄，改成 flex 排的列，欄位隨寬度逐段出現。**沒有停刊日就只講創刊**，不補「停刊年不詳」：30 本裡有 19 本查不到，那句話會把一整欄讀成雜訊
- 跨型別搜尋，文章／期刊／遊戲三個頁籤

## 編輯紀錄與貢獻者

所有寫入都留下 `EditLog`，記錄使用者、動作、對象與 diff。

- `/admin/edit-logs`：可依使用者、類型、動作篩選（僅 ADMIN）。這是**稽核**視圖，什麼都看得到，包含帳號變更
- `/admin/contributors`：貢獻排行與近期活動

**刪除紀錄記得下名字**：紀錄活得比資料久，只留 id 的話事後看不出刪掉的是什麼（`（已刪除 · cmsumll9k007x04joxpa2rhy1）`）。所以 DELETE 會把名稱寫進 `changes`，列表再從那裡把它讀回來，顯示成 `P.47（已刪除）`；`scripts/merge-game.ts` 這類合併另外寫 `mergedInto`，就顯示成 `P.47（已合併至 P-47）` 並連到存活的那筆。2026-08-17 之前的舊紀錄沒有這份資訊，仍是 id。

**貢獻的定義是編目工作**：排行榜與活動流排除 `entityType: "User"` 的記錄。改自己的顯示名稱、ADMIN 指派角色都是真實的編輯、也都留在稽核記錄裡，但不是在整理目錄——否則把名字改過去再改回來就能白賺兩次貢獻。匯入腳本（司書(NPC)）同樣不列入排行。

## 匯出

`/admin/export` 匯出整份目錄為 CSV，可指定單一期刊。UTF-8 BOM 開頭，Excel 直接開得起來。

**匯出是備份，匯入是批次建檔的入口，兩者刻意不對稱**：匯出的欄位只會比匯入多，也不保證匯出的檔餵得回匯入。所以卷號（`volume_number`）在匯出裡留著——它還在 schema、還有值，備份漏掉就不是備份——但範本與匯入頁的欄位說明不再提供它，因為後台表單也已經不顯示（見 [data-conventions.md](data-conventions.md#卷號沒有在表單上)）。

**備份要還原得回一個能用的站**，所以匯出也收整批只出現在後台的欄位（2026-08-30）：雜誌的 `magazine_slug`、`aliases`、`categories`、`ended_date`、`logo_image`，單期的 `issue_slug`、`issue_code`、`cover_image`、`toc_images`、`toc_reviewed_at`、`complete_at`、`issue_order`。少了它們，還原得回一堆資料卻還原不回站——網址全變成 cuid、圖全不見、期數排序全跑掉。`issue_code` 尤其：已經分享出去的 `/i/<code>` 網址只認它。

衍生欄位不收（`publish_sort`、`founded_sort`、時間戳、id），刊名時期與退役 slug 也不收——CSV 是雜誌／單期／文章三層的扁平格式，一本刊有幾筆刊名時期跟它有幾期無關，塞不進同一行。額外圖片（`Photo`）同理不收，但它歸的是「還沒決定」：它接手了原本的 `photos` 欄，而那一欄的網址本來備份得到，所以這是一筆保真度的淨損失，等關聯資料的匯出成形一起解（2026-08-31，見 [docs/plans/2026-08-31-photos-design.md](plans/2026-08-31-photos-design.md)）。**這份分類由 `src/__tests__/lib/export-schema-coverage.test.ts` 釘住**：schema 一加欄位，那支測試就會要求歸類成「收」「衍生不收」或「還沒決定」，因為備份漏欄不會有症狀，要到還原那天才發現。

需要登入才能下載。回應是串流的，單期以 50 筆為一批讀取，資料量成長不會撐爆記憶體。

### 匯出紀錄

每次匯出都在 `export_logs` 留一筆：匯出者、時間、範圍（期刊 id 與**名稱快照**，null 代表全部期刊）、筆數、IP 與 User-Agent。`/admin/export-logs` 看得到，**僅 ADMIN**——那一頁自己做伺服端角色檢查，不只靠側欄隱藏。

紀錄在第一個位元組送出**之前**就寫下，結束才回填 `rowCount`。所以中途斷掉的下載也留得下痕跡，而 `rowCount` 是 null 就是「這次沒跑完」。寫紀錄失敗（或匯出者無法歸屬，例如 API token 以外的情況）只會少一行紀錄，不會擋掉匯出——服務不了的匯出比少一行 log 更糟。

## 公開網址

遊戲與標籤頁以 **slug** 為網址（`/games/信長之野望`），不是 cuid。slug 由名稱產生：NFKC 正規化 → 小寫 → 保留中文與英數 → 其餘轉 `-`，撞到才接 `-2`。NFKC 擺在最前面是有原因的——`宇宙傳奇Ⅱ` 與 `宇宙傳奇Ⅲ` 的羅馬數字在正規化前會被當標點吃掉，兩款續作因此撞成同一個 slug。

**中文 slug 是刻意的選擇**：[Google 的 URL 結構指南](https://developers.google.com/search/docs/crawling-indexing/url-structure)建議用受眾語言的字詞，而這個站的讀者在台灣。代價是複製成純文字時會 percent-encode（`%E4%BF%A1%E9%95%B7...`），要乾淨英文網址的重點條目可在後台手動指定 slug。

舊的 cuid 網址不會斷：找不到 slug 就用 id 查，命中就 308 轉址到 slug 網址。後台網址維持 cuid——那些不會被分享。

**期刊走同一條路，但 slug 是 ASCII 而非中文**（`/magazines/ace`）。期刊 slug 是每一條單期網址的前綴，中文在這個位置會 percent-encode 成站上最常被分享的那類網址，所以 validator 只收 `[a-z0-9-]`。值不是從名稱產生的，而是沿用 [nostalibrary](https://gitlab.com/tzengyuxio/nostalibrary) 的代號（`content/magazines/<slug>/`），兩站因此共用同一組識別碼；上游沒有的三本另取自英文刊名：`astro`（星際遊樂雜誌）、`rgt`（舊遊戲時代）、`gamexpress`（電玩宅速配）。後台新增期刊時 slug 必填，CSV 匯入沒有這一欄則落到 cuid，之後由編輯補。

**單期的 slug 只需在該刊內唯一**（`/magazines/ace/issues/105`），因為期刊已經在路徑上。留空時從期號推出（`第163期` → `163`），但那只是預設值——期號的寫法太雜（重新編號、改名、合併號、以日期為號），撞到時是報錯要人取名，不自動接 `-2`。編目慣例見 [data-conventions.md](data-conventions.md#網址代號與期號是兩回事)。

單期這一段**還多收期號**：拿著實體雜誌的人讀到的是封底印的號碼，所以 `/issues/第163期` 也進得來，308 轉到 `/issues/163`。解析順序是 slug → 期號 → cuid，三者都限定在該刊內，別本刊的 cuid 一律 404。

文章沒有公開的單篇網址。

**路徑段刻意不縮寫**（不用 `/m/cgw/i/163`）。`/magazines/cgw/issues/163` 是 25 個字元，跟一個裸 cuid 一樣長，縮寫只省 11 個字元卻讓網址失去自我描述——貼到別處時它自己要能講出「這是某本雜誌的某一期」，這跟選中文 slug 是同一條理由。而且 `/games/`、`/tags/`、`/contributors/` 都是全稱，只縮這兩個會不一致。「短」這個預算留給日後的全域短碼（見 BACKLOG），那裡短才有意義。

## 認證與權限

- Auth.js v5 + Google OAuth 2.0
- 三種角色：VIEWER（瀏覽）／EDITOR（編輯）／ADMIN（管理）
- 首位使用者自動成為 ADMIN；也可用 `ADMIN_EMAILS` 指定
- 授權集中在 `src/middleware.ts`：寫入操作需要 EDITOR 以上，`/admin/users` 與 `/admin/edit-logs` 只給 ADMIN
- 批次腳本可用 `API_TOKEN` 以 Bearer token 認證寫入。**token 不能用於使用者管理，也不能用於讀取**——它是為無人值守的匯入而存在的
- 貢獻者也可以在 `/admin/profile` 自己產生 **per-user token**（`tocr_` 開頭）。拿它寫入等同本人操作：編輯紀錄署他的名，權限讀他當下的 role，所以**降級或刪帳號就等於撤銷他所有的 token**。只存 sha256，明碼在產生當下顯示一次；撤銷是標記不是刪列，不然事後看不出這支存在過
- **per-user token 與 `API_TOKEN` 的差別只在署名**：後者沒有人在背後，寫入一律掛給司書(NPC)，也照舊不列入貢獻排行。前者是某個人，所以算他的貢獻——`EditLog.via` 記下這筆是不是走 token 進來的，`/admin/edit-logs` 標成 API，貢獻排行合併計算但把數字分開留著
- token 一律不能讀，也不能拿來產生另一支 token（`/api/tokens` 只收 session）——能生 token 的 token 撤不掉
- `DEV_BYPASS_AUTH=true` 可在開發時免登入，該旗標在 production 一律無效

## 檔案儲存

生產環境用 Vercel Blob，沒有 token 時 fallback 到本地 `public/`。

上傳一律經過縮圖與轉檔：

| 用途 | 長邊上限 | 格式 |
|---|---|---|
| 目錄頁掃描圖（`issues/toc*`） | 2400px | **JPEG** |
| 其餘顯示用圖 | 1600px | WebP |

目錄頁維持 JPEG 是必要的——自架的模型後端解不開 WebP，會回 500。

## 被機器讀到（AEO）與分析

**AEO 的目標與 SEO 不同**：SEO 求「有人搜尋時排得上」，AEO 求「有人問模型時答得出來、而且答得對」。對這個站來說後者更值得投資——沒有人會用關鍵字搜「電腦玩家 1999 年 5 月號有哪些文章」，但會這樣問模型，而全世界只有這裡有那份目錄。

- **內容在初始 HTML 裡**：單期頁是 server component，目錄不靠 client 端渲染。抓取端不執行 JavaScript 也拿得到完整目錄，之後改動別破壞這一點
- **三層 JSON-LD**：`Periodical`／`PublicationIssue`／`Article`，文章掛在單期的 `hasPart` 底下——那是紙本目錄本來的形狀。見 `src/lib/structured-data.ts`
- **`/llms.txt`**：站台給模型的導覽，動態產生。除了怎麼定址與收錄了哪些雜誌，它特別講**什麼算可信**——EDTF 的精度是誠實的（`1999-05` 就是只知道月份，帶 `~` 是推定值）、改名之後另立書目、遊戲條目可能還有未合併的重複。模型答錯比答不出更該記下來，那是資料或標記出了問題
- **可引用的穩定網址是 `/i/<code>`**，寫進了 `llms.txt`：正規網址的每一段都可能因改名、重排、重填而變動，短碼不會
- **AI 爬蟲一律放行**，且不區分訓練用與即時檢索用（GPTBot 對 ChatGPT-User、ClaudeBot 對 Claude-Web）。這是決定不是預設值，理由寫在 `src/app/robots.ts`：這個站的目的是被引用，要讓模型答得對就得先讓它讀得到

**Google Analytics** 掛在 `src/app/(public)/layout.tsx`，所以 `/admin` 與 `/auth` 自然被排除——自己編目一整晚的點擊會蓋過真實訪客。measurement ID 走 `NEXT_PUBLIC_GA_ID`，**沒設就整個不掛**，本機與 preview 預設不送資料；設定方式見 [deployment.md](deployment.md#google-analytics)。目前沒有 cookie 同意橫幅，訪客量還小。

## 怎麼做

腳本在另一個 repo：`~/lab/nostalib-toolkit/scripts/tocr_create_issues.py`。
**可重複執行**，已存在的期號會跳過，不會建出重複資料。

```sh
env TOCR_TOKEN=<token> python3 ~/lab/nostalib-toolkit/scripts/tocr_create_issues.py
```

> **本機 `.env.production.local` 的 `API_TOKEN` 對 production 是 401**
> （2026-09-02 用一個空 body 的 POST 實測，production／local／preview 三份都不通，
> 沒有寫入任何資料）。要另外取一個能寫的 token。

做完之後回頭跑一次比對，確認那 49 張都落進「可以上傳」那一格：

```sh
python3 ~/lab/nostalib-toolkit/scripts/covers_vs_tocr.py
```

**是週刊，而且與站上既有的三期對得起來**——這三處是獨立的交叉驗證，不是自圓其說：

```
既有 No.52 = 2003-07-11   →  本次 No.53 = 2003-07-18     （+7 天）
既有 No.28 = 2003-01-17   →  本次 No.33 = 2003-02-28     （差 5 期 = 42 天）
本次 No.112 = 2004-09-24  →  既有 Vol.116 = 2004-10-22   （差 4 期 = 28 天）
```

> **唯一的例外：No.61（2003-09-12）到 No.63（2003-10-10）之間隔了 28 天**，
> 兩期之間少一週。兩個日期都放大重看過，不是誤讀——實際就是停刊或合刊了一次。
> 中間的 No.62 手上沒有實體，無從對照。

## 排序：兩本用不同做法

建完會呼叫 `/api/issues/reorder`：

- **電玩e世代**：38 期全部有 `publishDate`，直接依發行日重排
- **電腦玩家**：**只把特刊插到第 86 期（1998-09）之後，其餘 214 期的相對順序原封不動**。
  那份順序是人工整理過的，拿日期重排一次可能把沒有日期的期次沖到最後面

## 順帶：兩個對照關係值得記進資料

比對時發現這兩件事，站上的資料本身沒問題，但外部檔案對不上：

- **《GAME fans》站上以「新刊N號」為期號，掃描檔那邊用的是通卷號**
  （新刊3號＝通卷295、新刊5號＝通卷297）。兩邊都對，只是 key 不同，純字串比對必然失敗。
  已在 `~/Pictures/covers/raw/manifest.csv` 新增 `tocr_issue` 欄（存 `Issue.code`）解決
- **《電腦玩家》1998-09 有兩筆不同的東西**：月刊第 86 期（`publishDate: 1998-09`）
  與這次要建的特刊（`1998-09-01`）。日期近到只差一層精度，靠日期比對會配錯，
  也是靠 `tocr_issue` 這個明確外鍵才分得開

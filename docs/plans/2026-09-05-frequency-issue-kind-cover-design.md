# 發刊頻率、刊種與封面資訊 Design

Date: 2026-09-05

## 由來

三筆現在沒有地方放、只能寫進 `description` 或根本沒記的資料：

1. **發刊頻率**（週刊／月刊／季刊⋯⋯）——一本刊的基本識別，站上完全沒有。
2. **本刊與特刊的期數**——`Magazine.knownIssueCount` 記的是外部查來的總數，
   而站上自己的收錄數把試刊、特刊、正刊混在一起數，兩個數字並排顯示卻沒有
   一個說得出自己涵蓋什麼。
3. **封面資訊**（封面上的遊戲、真人，以及封面是誰畫的）——只能寫進
   `Issue.notes`，讀者看不到，長期配合的繪師（VOFan、曾正忠）等於沒有署名。

第 2 點是這輪真正的問題。〈已知總期數〉現行規範寫「算不算增刊，看來源怎麼算，
不是站上訂的規則」，那條在**已知數**上仍然成立——來源就是抄來的，改不了。但它
被誤用成了**收錄數**也不必有規則，於是「收錄 217・已知 216」只能配一句手寫警語。
新遊戲時代新增的兩本《攻略寶典》特刊把這件事推到了頭：差額會繼續長，而沒有任何
規則說得清那個差額是什麼。

## 決定

### 一、`Magazine.frequency`：單一值，存創刊值

不做複選。**頻率是時序屬性，不是並存屬性**——一本刊在任何一個時間點只有一種
頻率，「月刊＋雙週刊」複選起來既說不出先後也說不出主次。這跟 `categories` 用
陣列不衝突：那個是真的並存（同一期同時報 PC 與 TV 遊戲）。

值取**創刊時的版本**，中途改變（月刊轉雙週刊很常見）寫進 `description`——套用
〈單值欄位〉既有的規則，與 `publisher`、`nameParallel` 一致。理由是可機械判定：
「主要頻率」是主觀判斷，兩個編輯會填出不同答案。

不掛 `MagazineTitle`：頻率變動與改名不同步，切在刊名時期上會對不齊。

### 二、`Issue.kind`：站上自己定義收錄數

判準只有一條，而且只看封面：

> **這一冊有沒有拿到正刊的編號。** 進入正刊編號序列的是本刊；另立名目的
> （特刊、增刊、別冊、產品目錄）不是；正式創刊前的試刊也不是——出版社自己是
> 從創刊號開始數第 1 期。

它不要求判斷「這本重不重要」「算不算獨立出版品」，只要求看封面上那個編號，
所以兩個編輯會得到同一個答案。

**試刊獨立成一個值，不併進本刊。** 〈日期〉節對 `foundedDate` 已經訂過同一件
事（記創刊號、不記試刊號），理由是「創刊在期刊學上有明確定義，跨雜誌比較時才有
一致的基準；試刊號的數量與性質各家不一」。期數要的是同一個基準；併進本刊，
「收錄 N 期本刊」就失去那條基準線，而同一個站對「試刊算不算」給兩種答案比多一個
enum 值糟。

英文用 `PILOT`：期刊學上「試刊號」對應 pilot issue。`TRIAL` 在出版語境會讀成
試閱／試用訂閱，`PROTOTYPE` 是工業設計的詞。

特刊與增刊合成一個值。兩者在台灣這批雜誌的用法相當混，分開會逼錄入時每次判一次，
而判準拿不出來。

**刊種不影響序列。** 試刊仍然是正常的 `Issue`，`order` 照排在創刊號之前，
《電視遊樂快訊》拿試刊號當刊名時期起點也照舊；`kind` 只影響計數與標示。

### 三、已知數被超越就清掉

`knownIssueCount` 的職責是**站上還不夠完整時的參照**，不是權威本身。維基百科那個
數字在手邊資料比它詳實之後就沒有參照價值了，不必死守。規則可機械判定：

| 收錄本刊數 vs 已知數 | 意義 | 做法 |
| --- | --- | --- |
| 收錄 < 已知 | 還缺多少期 | 留著，這正是它的用處 |
| 收錄 = 已知 | 收齊了 | 留著，「收齊」本身是資訊 |
| 收錄 > 已知 | 來源已被超越 | **清空 `knownIssueCount` 與 source** |

第三列是《攻略寶典》那種情形的解——不是想辦法解釋差額，是承認那個數字已經不再
是參照。清空之後若日後找到更好的來源（國圖、藏家清單），再填新的。

`knownIssueCountSource` 仍然要寫明來源的計算範圍：它還在的時候，讀者得看得懂那個
數字涵蓋什麼。清空是人工動作，公開頁那句「收錄數多於已知期數」的說明因此保留，
但改寫成指向這條規則，不再宣稱「多半是增刊或特刊」——現在站上分得出來了。

### 四、封面資訊：被畫的分兩欄，製作端合一欄

分界不在「有幾種角色」，而在**這兩端本來就是不同的東西**：一端是「封面上有什麼」，
另一端是「封面是誰做的」。前者封閉（遊戲、真人兩種），後者開放（繪師、攝影、設計、
美術指導⋯⋯）。開放集合放進欄位名就是無底洞。

所以：開放的部分（角色種類）塞進**值**裡，封閉的部分留在**欄位**裡。

- `coverGames` — 封面上的遊戲
- `coverSubjects` — 封面上的**真人**
- `coverCredit` — 封面是誰做的。預設是繪者，直接寫「VOFan」；不是繪者時在值裡
  自帶角色詞，「攝影：陳某」「設計：某工作室」。**新角色永遠不需要新欄位，也不
  需要 migration。**

代價要認：角色資訊藏在值裡，程式讀不出來，`GROUP BY` 不了。這是刻意的——
「某繪師畫了幾本」的統計已經評估為效益不大，付這個代價現在等於零；真要的時候
從一個寫法一致的欄位回填也不難。

`coverGames` **不接 `Game` 關聯**：封面上的遊戲多半在目錄裡也有欄目，反查那條
路已經有人走了，再拉一條 `Issue → Game` 是重複的第二條路徑，兩邊還會不一致。

## 資料模型

```prisma
/// 發刊頻率。單一值：頻率是時序屬性，一本刊在任何時間點只有一種，複選說不出
/// 先後也說不出主次。存創刊值，中途改變寫進 description——同 publisher。
enum MagazineFrequency {
  WEEKLY       // 週刊
  BIWEEKLY     // 雙週刊（每兩週，一年約 26 期）
  SEMIMONTHLY  // 半月刊（每月兩期，一年 24 期）
  MONTHLY      // 月刊
  BIMONTHLY    // 雙月刊
  QUARTERLY    // 季刊
  IRREGULAR    // 不定期
}

/// 這一冊在雜誌自己的編號序列裡的身分。判準只看封面上的編號：進入正刊序列的
/// 是本刊，另立名目的（特刊、增刊、別冊、產品目錄）不是，正式創刊前的試刊也
/// 不是——出版社自己從創刊號開始數第 1 期。
///
/// 試刊獨立而不併進本刊，與 foundedDate「記創刊號不記試刊號」同一個理由：
/// 跨雜誌比較要有一致的基準線。只影響計數與標示，不影響 order。
enum IssueKind {
  REGULAR // 本刊
  PILOT   // 試刊
  SPECIAL // 特刊、增刊、別冊、產品目錄
}

model Magazine {
  // ...
  frequency MagazineFrequency?
}

model Issue {
  // ...
  kind IssueKind @default(REGULAR)

  // 封面上有什麼、封面是誰做的。前者封閉成兩欄（遊戲、真人），後者開放，
  // 所以角色種類寫在值裡而不是欄位名裡：「VOFan」預設是繪者，「攝影：陳某」
  // 「設計：某工作室」自帶角色詞。加一種角色不需要 migration。
  //
  // coverGames 不接 Game 關聯：目錄那條反查路徑已經存在，第二條只會不一致。
  coverGames    String[] @default([]) @map("cover_games")
  coverSubjects String[] @default([]) @map("cover_subjects")
  coverCredit   String?  @map("cover_credit")
}
```

`kind` 有 default 而且不可空：每一冊都有身分，「還沒判」與「是本刊」在這裡是同
一件事——絕大多數本來就是本刊，給 null 只會讓計數要多處理一種情形。

## 顯示

**刊系頁的期數**（`src/app/(public)/magazines/[id]/page.tsx`）分開講，不再硬湊成
一個數字比：

```
收錄 216 期，另有特刊 1、試刊 1 ・ 已知 216 期（維基百科；不含增刊）
```

特刊／試刊為 0 時整段不出現。電腦玩家現行是「收錄 217・已知 216」加一句警語，
改完自然對齊。

**列表頁的期數徽章**（`MagazineList.tsx`、`magazines/page.tsx`）用**本刊數**，
tooltip 補特刊與試刊。徽章只有兩三個字的寬度，塞不下三個數字。

**期列表**在特刊與試刊那幾列標一個字樣。期號本身多半已經寫著「試刊 3 號」
「即時戰爭遊戲特刊」，標示是給那些沒寫在期號裡、只印在封面上的。

**單期頁的封面資訊**在封面圖下方分行列出，三欄都空就整段不出現。

## 不做的事

- **不拆 `knownIssueCount` 成本刊／特刊兩欄**：特刊的外部總數幾乎查不到，拆完
  就是一欄永遠空著。已知數是抄來的單一數字，站上不替它分類。
- **不為封面攝影、封面設計開欄位**：見上，角色寫在 `coverCredit` 的值裡。
- **不把封面人物、繪師接成 `Tag` 關聯**：統計效益已評估為不大，關聯要付的是
  一整套後台重複列的介面。三個文字欄位是可升級的——寫法一致的話日後回填不難。
- **匯入不收新欄位**：匯入只收人打得出來的欄位，與匯出刻意不對稱（見
  `export-rows.ts` 開頭）。刊種由回填腳本處理，頻率與封面資訊在後台填。

`export-schema-coverage.test.ts` 明列匯出欄位與豁免清單，schema 一加欄位它就會
要求補上，所以匯出不會漏。

### `docs/data-conventions.md`

- 〈單值欄位／歷史值取創刊時的版本〉：把 `frequency` 列進去
- **新節〈刊種〉**：判準（只看封面上的編號）、三個值、試刊為什麼獨立、
  不影響 `order`
- 〈已知總期數〉**改寫**：現行「算不算增刊看來源」限縮成只管已知數；補收錄數
  自己的定義，補「被超越就清空」那張表
- **新節〈封面資訊〉**：三欄的分工、`coverCredit` 的角色詞寫法、
  **`coverSubjects` 只記真人**（遊戲角色如春麗、瑪利歐歸 `coverGames`，兩欄不
  分界會互搶，這是錄入時每次都要猶豫一下的成本）、空值代表「未查證」不是「沒有」

## 回填

`scripts/backfill-issue-kind.ts`，走 API 不走 SQL（直接 UPDATE 會漏掉 edit log），
冪等：

- **只看期號，不看標題**：標題講的是這一期的內容不是它的身分。對 2443 期正式站
  資料試跑過，讀標題會把《軟體世界》70+71、《電擊王》Vol.12、《電玩通》No.013 與
  No.044（標題都提到「別冊附錄」）誤判成特刊，而且一筆真陽性都沒多抓到。
- 期號含「試刊」「創刊準備」「預備號」→ `PILOT`
- 含「特刊」「增刊」「別冊」「特別號」「產品目錄」「寶典」→ `SPECIAL`
  （「寶典」是《新遊戲時代》的《正宗攻略寶典3》）
- 其餘 `REGULAR`（即 default，不必寫）

規則機械但不完備，跑完要人工掃一遍——這批刊只有幾本有試刊，特刊也是少數，掃得完。
掃完之後才輪到 `knownIssueCount` 的清空：那要逐本看收錄本刊數與已知數的關係，
是資料活，不進腳本。

`frequency` 與封面資訊沒有回填來源，空著等後台補。
